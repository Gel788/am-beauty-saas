# Am Beauty

Мультитенантный журнал салона красоты: записи, клиенты, услуги, мастера, график, оплаты и касса со сменами. Интерфейс на русском. Сделаны фазы 1 и 1b по `docs/TZ.md` и из фазы 2 онлайн-запись. Склада, лояльности и зарплат пока нет.

Поведение продукта описано в `docs/behavior`. Если сценария там нет, его нет и в продукте.

## Запуск

Нужны Node.js 22 и Postgres 16.

```bash
docker compose up -d
cp .env.example .env
npm install
npm run db:migrate
npm run db:seed
npm run dev
```

Приложение: http://127.0.0.1:43123

Миграции идут от суперпользователя (`MIGRATE_URL`), приложение подключается как `app_user` и подчиняется RLS. `npm run db:migrate` применяет файлы из `db/migrations` по порядку и помнит их в `schema_migrations`; база, созданная до появления раннера, подхватывается автоматически (001 помечается применённой, дальше идут новые). В Docker это `postgres` / `postgres` и база `ambeauty` на порту 5432.

## Онлайн-запись

Страница для клиентов: `/b/{салон}/{филиал}`, у демо-салона это http://127.0.0.1:43123/b/am-beauty/sadovaya. Её можно встроить на сайт через iframe; ссылку, код вставки и правила (шаг слотов, запись не раньше чем через N минут, горизонт, время брони, окно отмены, лимит записей на телефон) владелец настраивает в «Настройках».

Клиент проходит три шага: услуга, мастер и время, контакты. Выбранное время держится за ним 5–10 минут (`slot_holds`), подтверждение создаёт запись с `source = online`, а клиента находит по телефону или создаёт. После записи клиент получает ссылку `/booking/{token}`: до окна отмены запись отменяется сама, позже уходит просьбой администратору (видна в истории записи).

Публичные запросы идут без сессии. Салон находят функции `public_branch_lookup` и `public_booking_lookup` (SECURITY DEFINER, возвращают только id), дальше всё работает под RLS этого салона.

## Отчёт дня

Раздел «Отчёт дня» (`/reports`, владелец, администратор, бухгалтер) показывает за выбранный день выручку по проведённым оплатам за вычетом возвратов с разбивкой на услуги, товары и чаевые и по способам оплаты, записи по итогам (завершено, отменено, неявки, онлайн), загрузку мастеров (занятое время к рабочему по графику) и списки платежей и записей дня.

## Деньги и время

Суммы хранятся целыми копейками. Время записи — `timestamptz` в UTC плюс снимок часового пояса филиала. Сетка журнала — 5 минут. Запись не может перейти через местную полночь.

## Что входит в эту фазу

**Фаза 1.** Авторизация, тенант и филиал, роли, услуги, мастера и недельный график, клиенты, журнал (создание, правка, отмена, статусы, конфликты, перенос и изменение длительности), открытие смены и проведение оплаты.

**Фаза 1b — касса** (`docs/behavior/04-cash-shifts.md`):

- Закрытие смены в два шага: «Закрыть смену» переводит её в `closing` и блокирует новые оплаты, возвраты и аннулирования; затем пересчёт наличных, сверка безнала и Z-отчёт (SHIFT-CLOSE-01). Пока смена закрывается, её можно вернуть в работу — тому, кто начал, или владельцу (SHIFT-CLOSE-02). Закрытая смена не переоткрывается, её итоги заморожены снимком (SHIFT-CLOSE-03/04).
- Ожидаемые суммы по способам: наличные = старт + приход − возвраты (сдача уже вычтена), безнал принимается по ожидаемому, если кассир не ввёл другое. Расхождение больше порога филиала (`shift_variance_threshold_minor`, по умолчанию 0) или несовпадение безнала требует причину.
- Возвраты полные и частичные (PAY-REFUND-01/02): по сумме или по строкам, не больше остатка, деньги уходят тем же способом, что пришли (безнал первым). Возврат проводится в текущей открытой смене. Полностью возвращённый платёж получает статус `refunded`; возврат погашения долга возвращает долг клиенту.
- Аннулирование (PAY-VOID-01): только наличные, только в той же ещё открытой смене и без возвратов; причина обязательна. Остальное — через возврат.
- Оплаченная сумма записи, долг и выручка дашборда считаются нетто: приход минус возвраты, аннулированные не учитываются.
- В филиале не больше одной активной (`open` или `closing`) смены. Предупреждение, если смена открыта 36+ часов.
- Экран «Касса»: текущая смена, ожидаемое по способам, разбивка выручки, платежи с возвратом и аннулированием, приход без записи, история смен, Z-отчёт с печатью. В карточке записи — список платежей и возврат; при отмене предоплаченной записи карточка сама предлагает возврат.
- Аудит: `shift.opened`, `shift.closing_started`, `shift.closing_cancelled`, `shift.closed` (с расхождением), `payment.posted`, `payment.refunded`, `payment.voided`.

API кассы: `GET /api/shifts`, `GET /api/shifts/current`, `POST /api/shifts/open`, `POST /api/shifts/:id/start-closing`, `POST /api/shifts/:id/cancel-closing`, `POST /api/shifts/:id/close`, `GET /api/shifts/:id/report`, `GET /api/payments?shiftId=|date=`, `POST /api/payments/:id/refund`, `POST /api/payments/:id/void`, `GET /api/appointments/:id/payments`.

Не сделано: неделя/месяц в журнале, онлайн-запись и модули фаз 2–4, корректировки закрытой смены отдельным `adjustment`-платежом (SHIFT-CLOSE-04, вторая часть). Не было файлов `design-direction.md` и `yclients-parity-matrix.md` — экран кассы собран в стиле утверждённых макетов журнала и дашборда.
