# Поведение: клиенты

**ID prefix:** `CL-`  
**Фаза:** P1 CRUD; merge/RFM/import P2

---

## 1. Сущность Client

| Поле | Правила |
|---|---|
| name | обяз., trim, 1–120 |
| phones[] | ≥1 для Save в большинстве сценариев; primary phone unique в tenant (нормализованный) |
| email | optional, validate |
| tags[] | |
| notes | внутренние |
| source | walk-in / online / instagram / … |
| balance_minor | долг (>0 клиент должен) |
| birth_date | optional |
| consents | marketing/personal data flags P2 |
| deleted_at | soft |

## 3. Сценарии

### CL-CREATE-01 · Создание из раздела Клиенты
- Форма: имя, телефон, optional fields.  
- Дубликат телефона → block + link на существующего.

### CL-CREATE-02 · Из записи (см. TT-CREATE-03)
- Тот же пайплайн уникальности телефона.

### CL-EDIT-01
- Save с version; смена primary phone — re-check unique.

### CL-DELETE-01 · Soft-delete
- Если есть будущие appointments — confirm «отменить N записей / оставить».  
- Default: нельзя soft-delete без решения по future (modal choice).  
- История визитов сохраняется.

### CL-SEARCH-01
- По имени, телефону (suffix), email.  
- Debounce 200ms; min 2 chars (кроме полного телефона).

### CL-MERGE-01 · Объединение дублей
- Кандидаты: одинаковое имя из двух и более слов (порядок слов, регистр и ё не важны), одинаковый email, одинаковые последние 10 цифр телефона. «Это разные люди» убирает группу из списка.
- Переносятся также сертификаты, абонементы, ссылки на оплату, сообщения, Telegram (если у основной нет), телефоны (как дополнительные); пустые поля заполняются, заметки склеиваются, согласия — самое раннее ПД и «или» по рекламе.
- Выбрать primary + secondary.  
- Перенос: appointments, payments, loyalty, notes, tags.  
- Secondary → merged_into_id + deleted.  
- Audit full.

### CL-BALANCE-01
- Отображение долга; CTA погасить → PAY-DEBT.  
- Ручная корректировка баланса — owner/accountant + reason.

### CL-HISTORY-01
- Timeline: визиты, оплаты, статусы no_show, сообщения P2.  
- Фильтр по филиалу если сеть.

### CL-IMPORT-01 · CSV / XLSX
- Файл читается в браузере: CSV (`;` `,` tab, UTF-8 или cp1251) или первый лист .xlsx (выгрузка YClients, Altegio, Excel).
- Колонки угадываются по заголовкам (имя/ФИО/клиент, телефон, email, дата рождения, категории, визиты, последний визит, сумма продаж, бонусы, долг/баланс, комментарий), админ правит сопоставление. Обязательны имя и телефон.
- Проверка (dry run) ничего не пишет: сколько новых, сколько уже в базе (по телефону), повторы внутри файла (сливаются в одну строку), строки с ошибкой и причина.
- Телефон уже в базе: «дополнить» (пустые поля, метки, история) или «пропустить». Деньги существующих карточек не меняются.
- Новые карточки: source `import`, долг → balance_adjustments, бонусы → bonus_ledger (manual), визиты/последний визит/сумма → `imported_*` (видно в карточке «до переезда»).
- Согласие 152-ФЗ переносится только галочкой «клиенты давали согласие» (source `import`); согласие на рекламу не переносится.
- До 20 000 строк за раз, одной транзакцией.
- Отмена импорта скрывает созданные им карточки, кроме тех, где уже есть записи, оплаты или объединения; телефоны освобождаются.

---

## 4. Edge cases

1. Два одинаковых имени, разные телефоны — ок.  
2. Пустой телефон только для «черновика» из журнала до Save — нет; телефон обяз.  
3. Международный номер — хранить E.164.  
4. Merge при open debt на обоих — суммировать balance.

### CL-TECH-01..04 Техкарта клиента (сделано)
- **CL-TECH-01:** аллергии и противопоказания (до 500 символов). Первая запись требует отметки о согласии клиента на хранение сведений о здоровье (152-ФЗ, ст. 10), время согласия сохраняется. Изменения — в аудите.
- **CL-TECH-02:** формулы и заметки мастера по видам (окрашивание, ногти, ресницы, брови, уход, заметка), с автором и визитом. Удаляет автор или администратор.
- **CL-TECH-03:** фото «до / после», уменьшаются на устройстве до 1600 px (≤ 1,5 МБ), сервер принимает только настоящие JPEG/PNG/WebP (проверка сигнатуры), до 60 фото на клиента. Удалённое фото стирается из базы.
- **CL-TECH-04:** предупреждение «⚠ Аллергия… Противопоказания…» в карточке записи и в «Моём дне» мастера; там же последняя формула.
- Доступ: владелец, администратор, мастер; бухгалтер не видит. При объединении дублей формулы, фото и обе аллергии сохраняются.
